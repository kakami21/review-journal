# Design

## Context

目的は `proposal.md` の Why を参照する。現在の `src/pages/index.astro` は、幅 `max-w-4xl` の1列の中に記事・ノート・口コミを配置している。`SiteLayout.astro` はサイト名・紹介文・フッターを全ページで共有しているが、ウィジェットは表示していない。

導入済みのEmDash 1.3.1では、`WidgetArea` が指定名のエリアを取得し、保存された順番で表示する。コンテンツブロックは、画像や段落を保存する形式であるPortable Textとして保持され、標準の `PortableText` で描画される。エリアが存在しない場合やウィジェットがない場合は、`WidgetArea` 自体が何も出力しない。

確認した主な実装は `node_modules/emdash/src/components/WidgetArea.astro`、`WidgetRenderer.astro`、`PortableText.astro`、`Image.astro`。公式の使い方は [Widget Areas](https://docs.emdashcms.com/guides/widgets/) を参照する。

## Goals / Non-Goals

**Goals:**

- 標準のウィジェット編集と表示をつなぎ、サイト固有の処理を配置と装飾に絞る。
- 自己紹介を登録する前にも既存のトップページを閲覧できるようにする。
- 名前や紹介文を変更するたびに、サイトのコードを編集する必要をなくす。

**Non-Goals:**

- 画像・名前・紹介文を個別の入力欄として管理する専用画面や保存形式は作らない。
- コンテンツブロックの段落を解析し、名前や紹介文として取り出す処理は追加しない。
- 自己紹介のためのブラウザ側のJavaScriptや独自APIは追加しない。

## Decisions

### 1. トップページの投稿一覧の前に置く

`src/pages/index.astro` の本文コンテナー内で、`sections.map(...)` の前に配置する。サイト紹介文を読んだ後、投稿へ進む前に書き手が分かり、投稿がまだなくても表示できる。

右側への配置も考えられるが、現在の1列の本文幅を変える必要がある。今回は本文と同じ幅のカードとし、スマートフォンでも同じ順番で読めるようにする。共通レイアウトへの配置は、トップページだけに表示する要件と合わないため採用しない。

### 2. 専用エリアに標準のコンテンツブロックを一つ登録する

エリアの識別名を `home-author-profile`、管理画面上の表示名を「トップページの自己紹介」とする。エリアの説明には「トップページの紹介文と投稿一覧の間に表示」と記載する。以前作った「メインサイドバー」は変更しない。

一つのコンテンツブロックに次の順番で登録する。

| 管理画面の場所 | 登録する内容 |
| --- | --- |
| ウィジェットのタイトル | この日記を書いている人 |
| 本文の最初 | メディアから選んだアイコン画像。代替テキストも設定する |
| 次の段落 | 名前。太字にする |
| その後の段落 | 短い自己紹介。2〜3行程度を目安とする |

画像・名前・紹介文を別々の専用フィールドにする案は、独自の編集機能が必要になる。今回は標準の本文編集で十分なため採用しない。登録数や文字数の独自検証も作らず、一つのブロックで運用する手順を示す。

アイコンの未登録は許容する。画像を削除した場合は保存済みの文章だけを表示し、固定の画像やダミーの紹介文で補わない。

### 3. 標準の表示部品と、エリアに限定したCSSを使う

`src/pages/index.astro` で `emdash/ui` の `WidgetArea` を読み込み、`name="home-author-profile"` と専用クラス `home-author-profile` を渡す。中身がないときに空のカードが残らないよう、外側に常時表示される見出しや装飾用の枠を作らない。

`src/styles/global.css` に、`.home-author-profile` の中だけに適用するスタイルを追加する。標準部品が出力する `.widget`、`.widget__title`、`.widget__content` と画像要素を対象にする。標準部品のHTMLを独自実装へ置き換える必要はない。

カードの面色は既存の `bg-base-100` 相当とし、2pxの濃い枠線と右下4pxの影を既存カードに合わせる。アイコンは80px程度の円形とし、画像、名前、紹介文を上から順に並べる。画像は円形の枠内で切り抜き、文章は折り返す。画面幅による2列への切り替えは加えない。

エリアが未作成・空の場合は `WidgetArea` の標準動作に任せる。DB障害などを「未登録」と見なす例外処理は追加しない。

### 4. 内容は環境ごとに管理画面で登録する

現在のトップページはサーバーでHTMLを生成し、`Cache-Control: no-store` を返している。この設定を維持する。ウィジェットの保存内容を次のページ読み込みで取得するため、内容の変更だけならビルドやサイトの再公開を必要としない。投稿とは異なり、ウィジェットには今回新たに下書き・公開の操作を設けない。

`docs/setup.md` に、エリアの作成、コンテンツブロックの登録、画像の差し替え、文章の更新、非表示にするための取り外しを記載する。previewとproductionは保存先が別なので、それぞれの管理画面で必要な内容を登録する。既に設定済みの環境へseedを再適用したり、今回のためにマイグレーションを追加したりしない。

## Risks / Trade-offs

- 標準の本文編集では、画像・名前・紹介文を一つの文章として扱う。順番や個数を強制できない → 登録手順に一つのコンテンツブロックの構成例を示す。
- 標準部品のHTMLに合わせたCSSは、EmDashの更新で影響を受ける可能性がある → 専用クラスの中だけに限定し、更新時に画像と本文の表示を確認する。
- 管理画面で保存すると、その環境で公開される内容が変わる → 保存前に対象環境を確認する手順を示す。今回の計画作成では登録を行わない。
- 独自の名前・紹介文欄が将来必要になる可能性がある → 今回の標準ウィジェットの利用とは分け、必要になった時点で変更として検討する。

## Migration Plan

1. 次の実装作業で、トップページへの配置・CSS・導入手順を追加する。
2. `npm test`、`npm run build:preview`、`npm run build:production` を実行する。ビルドには型チェックも含まれる。
3. previewへの公開時に、エリア未作成でも既存のトップページを閲覧できることを確認する。管理画面で自己紹介を登録し、編集・画像差し替え・取り外しを確認する。
4. 375pxと1280pxでレイアウトを確認し、`/reviews` と個別記事・存在しない投稿には表示されないことを確認する。
5. 本番へ公開する場合は `docs/deploy-production.md` に従い、本番側で内容を登録して主要ページを確認する。本番公開は仕様作成とは別に扱う。

非表示に戻す場合は対象エリアからウィジェットを取り外す。サイトの変更を戻す場合は直前のWorkerへ戻し、CMSのエリア・本文・画像は保持する。

## Open Questions

- 実際に使うアイコン・名前・自己紹介の文面は、実装後の管理画面で登録するときに決める。保存方法や表示の仕様には影響しない。
