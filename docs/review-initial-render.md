# 口コミ一覧の初回表示

`/reviews`はリクエスト時にAstroから公開口コミを取得し、本文を含むHTMLを返す。Reactは受け取った初期値を使い、訪問年月順と評価順の切り替えを担当する。公開API `/api/reviews` も同じ取得処理を使う。

## 取得と表示の比較

| 項目 | 変更前 | 変更後 |
| --- | --- | --- |
| 初回HTMLの本文 | 含まない | 含む |
| ブラウザからの初回一覧API通信 | 1回 | 0回 |
| CMS公開コレクションの取得 | 100件ごとに1回 | 同じ |
| 最終取得日時の取得 | 1回 | 1回 |
| 本文表示に必要な順序 | HTML取得→React起動→API通信→表示 | HTML取得→表示 |

取得回数は公開クエリのページ送りを含む単体テストで確認した。従来のAPIと今回の画面は同じ`createCmsReviewApiDependencies().getAll()`を呼ぶため、CMS問い合わせの重複はない。初回通信の削減と引き換えに、HTML応答はCMS取得の完了を待つ。

実環境の表示時間は未計測。検証環境で変更前後の同じデータを使い、ブラウザのキャッシュを無効にして複数回取得し、TTFBと本文表示時刻の中央値を比較する。初回表示時に`/api/reviews`が発生しないこともNetworkで確認する。単体テストの実行時間は通信時間を含まないため、表示時間の改善量として扱わない。

## エラーと日付

取得に失敗した場合はHTTP 500と再試行の案内を返し、0件とは表示しない。途中まで取得できた内容も表示しない。正常な空一覧はHTTP 200、0件、未収集なら「未実行」と表示する。公開版専用クエリを使うため、下書き・編集中の本文は含めない。

最終取得日時はサーバーとブラウザのタイムゾーンに左右されないよう日本時間で表示する。訪問年月は取得元の`YYYY-MM`を`YYYY/MM`へ整えるだけで、日付を補完しない。店舗リンクと口コミIDのフラグメントは維持する。
