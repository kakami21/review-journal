# 食べログと手入力の共通投稿

`/reviews` は食べログの口コミと、手入力の口コミ・ノート・記事をまとめて表示する。公開版をAstroで読み、初回HTMLに本文を含める。`/api/posts` は同じ変換を使う共通API。既存の `/api/reviews` と口コミの `#食べログID` リンクを維持する。

## 保存先と公開範囲

- 食べログ：既存の `reviews`。ID・内容・公開状態・改訂・予約・ゴミ箱を移行しない。取り込みは引き続き追加のみ。
- 手入力：新しい `entries`。種類は `review` / `note` / `article`、取得元は共通モデルで `manual` とする。
- 両方ともEmDash標準の下書き・改訂・公開予約・ゴミ箱を利用する。公開一覧は管理用一覧を使わず、`status: published` の公開スナップショットを全ページ取得する。
- 共通モデルの `id` は既存リンク用、`contentId` はCMSの不変ULID。手入力のアンカーは `manual-ULID`。

## 既存環境へのスキーマ追加

`seed/seed.json` は新規DBの初期設定用であり、設定済みDBには再適用されない。先行PR #69を取り込んだ環境で、公開切り替え前に次の追加を行う。検証用・本番用それぞれで別のAPIトークンと接続先を指定する。

1. D1のバックアップを取得し、既存 `/api/reviews` の件数と内容を保存する。
2. `schema:read`・`schema:manage` を許可した管理者APIトークンを `EMDASH_API_TOKEN` に設定する。トークンをコマンド履歴や文書へ記録しない。
3. `node scripts/setup-entries.mjs https://検証先のオリジン` を実行する。スクリプトはCMS標準APIで `entries` とフィールドを追加し、投稿や既存口コミを更新しない。途中失敗後は同じコマンドで再開できる。既存フィールドと定義が異なる場合は停止する。
4. 管理画面に「手入力投稿」が現れ、種類・タイトル・本文を入力できることを確認する。
5. 下記の操作確認後、同じ手順を本番へ適用する。

`entries` が未設定なら共通一覧はHTTP 500と取得失敗の案内を返す。未設定を0件として扱わないため、スキーマ追加を公開より先に行う。

## 管理画面と公開画面の確認

1. 「手入力投稿」で口コミ・ノート・記事を作成する。タイトルと種類は必須。口コミだけ店舗名・訪問年月（`YYYY-MM`）・0〜5の評価も必要。ノートと記事は店舗名・評価なしで保存できる。
2. 下書き保存した本文が `/reviews` と `/api/posts` に出ないことを確認する。
3. 公開して表示を確認し、公開後に本文を変更して下書き保存する。公開版に編集中の本文が混ざらず、再公開時だけ反映されることを確認する。
4. 公開予約、非公開化、ゴミ箱移動・復元を行い、公開条件を満たす投稿だけ表示されることを確認する。
5. 種類の絞り込みと口コミの評価順を操作する。評価順は口コミだけを対象とする。ノート・記事への切り替えで新しい順へ戻る。
6. 既存口コミのリンク・年月・食べログのいいねを確認する。取り込みを再実行し、既存口コミの編集・ゴミ箱・公開状態が変わらず、同時取り込みでも重複しないことを確認する。
7. スマートフォン幅で本文の折り返しと操作を確認する。

## データ保全と復旧

この変更は旧DBテーブル・適用済みSQL・既存の口コミスキーマを削除しない。復旧時はアプリを変更前へ戻し、追加済み `entries` は削除せず保管する。旧版は手入力投稿を表示しないが、口コミは従来どおり参照する。手入力データを保持したまま再公開できるよう、コレクションやフィールドの削除で復旧しない。

写真はIssue #52、アプリ内いいねはIssue #46で扱う。
