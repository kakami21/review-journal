# 手入力投稿の写真

手入力のreview・note・articleに任意の写真を1枚添付する。管理画面の「手入力投稿」で「投稿の写真」からアップロードまたはメディアライブラリの写真を選び、公開する。公開済み投稿も編集から追加・差し替え・取り外しできる。写真の説明は画像の代替テキストに入力する。

共通カードでは本文の下に写真を表示し、元の縦横比を維持する。写真なしの場合は画像枠を表示しない。既存投稿への一括追加、食べログ由来の口コミへの写真項目追加、料理ごとの写真、複数写真のギャラリー、自動収集は対象外。

写真を取り外す操作は投稿との関連を外す。元のファイルはメディアライブラリに残り、他の投稿で再利用できる。写真の編集も本文と同じ公開版・下書きの規則に従い、再公開まで公開カードには反映されない。ただし画像ファイルの配信URL自体は公開URLであり、機密写真の保管には使わない。

## 保存と配信

EmDash標準のimageフィールドとR2アダプターを使用する。画像アップロードと管理はCMSの認証付きAPIに任せる。写真の保存キー・説明・寸法を投稿に保持し、公開APIでは表示用URLへ変換する。アップロード形式はJPEG・PNG・WebP・AVIF・GIF。ファイルサイズや実データの検証はEmDash標準のアップロード処理に従う。

R2バケットを公開せず、標準の `/_emdash/api/media/file/…` で配信する。R2アクセスキーや署名URL用の秘密値は追加しない。メディアと同じ保存先に入るCMSバックアップを公開しないため、バケットの公開ドメイン・r2.devアクセスは有効にしない。

| 環境 | 設定 | バケット |
| --- | --- | --- |
| 開発・検証 | wrangler.astro.jsonc | table-notes-media-development |
| 本番 | wrangler.astro.production.jsonc | dining-archive-media |

開発もリモートR2に接続するため、ローカル操作の画像は開発用バケットへ保存される。

## 導入手順

1. 対象アカウントでR2が利用可能であることを確認し、バケットを環境ごとに作成する。公開アクセスは有効にしない。

   ```sh
   npx wrangler r2 bucket create table-notes-media-development
   npx wrangler r2 bucket create dining-archive-media
   ```

2. 対象D1をバックアップする。既存サイトでは、[共通投稿の導入手順](posts.md#導入手順)に従い、対象環境の管理トークンで更新済みの準備処理を実行する。

   ```sh
   node scripts/prepare-entries.mjs https://対象のオリジン
   ```

   既存のentriesに任意のphoto項目だけを追加する。既存投稿の本文・公開状態・履歴を変更せず、reviewsにも触れない。seedの変更だけでは既存サイトに項目は追加されない。

3. 開発環境で画像アップロード、追加・差し替え・取り外し、写真なし、縦長・横長、狭い画面、未ログインでのカードと画像表示を確認する。下書き編集が公開カードへ混ざらないことも確認する。
4. [リリース手順](releases.md)に従って公開する。CIの公開用Cloudflareトークンには対象R2を利用するWorkerのデプロイに必要な権限があることを確認する。本番公開後も同じ操作を確認する。

DBのバックアップに画像ファイル本体は含まれない。R2のファイルは別途保全する。旧版へ戻す場合も、追加したphoto項目・メディア・R2バケットは削除せず保持する。
