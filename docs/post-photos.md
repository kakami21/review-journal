# 手入力投稿の写真

手入力の口コミ・ノート・記事には、管理画面の「投稿の写真」から任意の写真を1枚追加できる。公開カードでは本文の下に表示し、写真がない投稿には画像枠を出さない。追加・差し替え・取り外しは通常の投稿編集で行い、再公開するまで公開版の写真を維持する。画像の説明は代替テキストへ入力する。

画像欄とアップロードはEmDash標準のメディア管理を使う。写真を取り外してもメディアライブラリのファイルは残る。食べログの口コミには画像欄を追加せず、写真の自動収集も行わない。

## 保存先と配信

| 環境 | 設定 | R2バケット |
| --- | --- | --- |
| 検証・開発 | `wrangler.astro.jsonc` | `table-notes-media-staging` |
| 本番 | `wrangler.astro.production.jsonc` | `dining-archive-media` |

R2は非公開とし、`r2.dev`や公開ドメインを有効にしない。EmDashの標準ルート `/_emdash/api/media/file/…` から画像を配信する。CMSバックアップも同じ保存先を使うため、バケット全体を公開しない。R2アクセスキーは不要。

公開カードは公開スナップショットだけを読む。ただし、メディアの配信URL自体は投稿の公開状態に関係なくアクセスできるため、機密画像の保管には使わない。

カードでは元の縦横比と寸法を保持し、表示幅をカード幅以内に収める。画像は遅延読み込みする。不正な画像参照は取得エラーとし、成功した空一覧に置き換えない。

## 導入と確認

1. 対象アカウントでR2を有効にし、環境別の非公開バケットを作成する。

   ```sh
   npx wrangler r2 bucket create table-notes-media-staging
   npx wrangler r2 bucket create dining-archive-media
   ```

2. 対象D1のバックアップを取得する。既存サイトでは、管理トークンを環境変数 `EMDASH_API_TOKEN` に設定してスキーマ追加処理を実行する。

   ```sh
   node scripts/setup-entries.mjs https://対象環境のオリジン
   ```

   `entries`に不足する項目だけを追加する。既存の本文・公開状態・改訂・口コミの保存先には触れない。実行済みなら再実行しても項目を重複追加しない。seedの更新だけでは設定済みサイトのスキーマは変わらない。

3. 検証環境へ公開し、管理画面で写真なし・追加・差し替え・取り外しを確認する。下書きの写真が再公開前に公開カードへ混ざらないこと、未ログインでの画像配信、390px幅で縦長・横長の写真を確認する。
4. 本番公開前にも保存先の分離を確認し、公開後に同じ操作を確認する。

本PRではバケット作成、稼働中DBのスキーマ更新、デプロイを行っていない。これらの設定と実環境確認が完了するまでIssue #52を残す。

## 保全と復旧

D1のバックアップには画像本体を含まない。R2のファイルも別途保全する。旧版へ戻す場合も、追加したphoto項目・既存データ・R2バケットは削除せず保持する。取り外した写真のファイル削除は、利用先を確認してからメディア管理で行う。
